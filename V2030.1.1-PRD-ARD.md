# autofde v2030.1.1 — PRD / ARD

**Repository:** `seanchatmangpt/autofde`  
**Ecosystem role:** product / EXPLOIT-only autonomous FDE  
**Depends on:** `ggen`, `gymact`, `mfact`, `open-ontologies`, `star-toml`  
**Release:** Chatman Ecosystem v2030.1.1  
**Standing conferred:** `UNKNOWN`.

## Product requirement

`autofde` SHALL be the exploit-only product that performs bounded autonomous Forward Deployed Engineering against admitted enterprise subjects. Its v2030.1.1 target is to accept outcome-level intent plus constraints/authority, discover the real environment, select from admitted candidate solutions, manufacture the required changes, actuate only through BRCE, verify postconditions, and return receipts.

North-star interaction:

> **Here is the outcome, authority boundary, budget, risk tolerance, and policy. Determine what is possible, prove what is lawful, manufacture what is required, execute only what is authorized, and return the receipts.**

## Required capabilities

1. Preserve its canonical ontology capsule and EXPLOIT-only mode; laboratory exploration remains in `autofde-lab`.
2. Discover infrastructure, applications, topology, identity, process, observability, cost, marketplace, security, and contract facts into admitted observations.
3. Consume `gymact` world/action models and graduated policies without inheriting lab/simulation authority.
4. Consume public semantics from `open-ontologies`, admitted config from `star-toml`, projections from `ggen`, and required formal certificates from `mfact`.
5. Implement the bounded lifecycle: DISCOVER -> MODEL -> DIAGNOSE -> SIMULATE/COMPARE -> PLAN -> CONSTRUCT -> ADMIT -> AUTHORIZE -> BRCE DO -> VERIFY -> RECEIPT -> REPLAY -> OBSERVE.
6. Support multi-cloud, Kubernetes, Terraform/IaC, SaaS/platform, marketplace, security, cost, migration, remediation, and process use cases through capability projections rather than provider-owned product semantics.
7. Separate SELECT, CONSTRUCT, and DO. Knowledge hooks manufacture intents only.
8. Preserve hard cost, region, policy, security, compliance, data-residency, and reversibility constraints.
9. Produce exact receipts for every consequential external mutation.

## Architecture requirements

```text
enterprise intent + authority + observed world
        -> O*
        -> canonical enterprise graph
        -> admitted candidate frontier
        -> selected plan
        -> ggen construction
        -> formal/runtime admission
        -> authority intersection
        -> BRCE
        -> external consequence
        -> postcondition verification
        -> receipt + replay
```

AutoFDE SHALL NOT use raw LLM output as execution authority. A planner, model, theorem, hook, marketplace event, or generated script is never an ambient DO credential.

## Marketplace/cloud requirement

The product SHALL consume canonical cloud and commerce semantics and project them into provider-specific APIs. AWS/Azure/GCP are not privileged architectural roots; Oracle, IBM, SAP, Salesforce, ServiceNow, Snowflake, Databricks, Alibaba, sovereign/private platforms, and future providers must fit the same capability/admission model where supported.

## Acceptance for v2030.1.1

A crown demonstration must execute a real bounded FDE task end-to-end and show:

- exact discovered subject;
- admitted observation/world model;
- explicit objectives and hard constraints;
- evaluated alternatives where alternatives exist;
- deterministic/replayable manufactured artifacts;
- required formal/runtime admissions;
- exact authority for the selected DO;
- brokered external actuation;
- observed postcondition;
- receipt and replay evidence;
- typed boundaries for unsupported/blocked/refused alternatives.

Simulation, source inspection, compilation, or a workflow definition alone cannot satisfy this acceptance criterion.

## Falsifiers

The architecture is falsified if AutoFDE directly executes model output; if a simulated cloud action is reported as live execution; if marketplace/provider schemas become canonical business semantics; if authority is inferred from credentials; or if a consequential mutation can complete without a receipt.

## Ecosystem contract

`autofde-lab` explores; `autofde` exploits. `gymact` models worlds/actions. `ggen` constructs. `mfact` certifies selected formal claims. `star-toml` admits configuration. BRCE is the exclusive DO path. AutoFDE may coordinate these capabilities but may not collapse their evidence or authority boundaries.
